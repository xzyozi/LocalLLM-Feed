# Git Commit Message Conventions

このプロジェクトのコミットメッセージ規約です。一貫性のある分かりやすい履歴を保つため、この規約に従ってください。

> 基本形式・運用ルール（ブランチ切り替え、コミット前のuser確認など）は
> `project-basics.md` を正とします。本ファイルは `project-basics.md` の
> 種別一覧を補足・拡充したものです。

---

## フォーマット

コミットメッセージは以下の形式で記述します。

```
[種別] 概要
```

- 概要部分は**日本語**で記述します。
- 種別は必ず `[ ]` で囲みます。

### 例
```
[feat] Alembicバージョンスクリプトの追加
[update] 画面遷移ロジックのリファクタリング
[fix] エラーメッセージのタイプミス修正
```

---

## 種別一覧

`project-basics.md` の4種別（`feat` / `fix` / `docs` / `other`）に加えて、
`other` が広義になりすぎないよう、以下の種別を追加で定義します。

| 種別         | 用途                                              | 例                                  |
| ------------ | ------------------------------------------------- | ----------------------------------- |
| `[feat]`     | 新機能・新規ファイルの追加                        | `[feat] ログイン画面追加`           |
| `[fix]`      | バグ修正                                          | `[fix] NULLチェック漏れの修正`      |
| `[update]`   | 既存機能の更新・改善（新機能ではないもの）        | `[update] 検索処理の高速化`         |
| `[refactor]` | 挙動を変えないコードのリファクタリング            | `[refactor] クラス構造の整理`       |
| `[remake]`   | 大規模なリファクタリング・機能の作り直し          | `[remake] 認証モジュールの再設計`   |
| `[style]`    | コードの意味に影響しないスタイル変更（空白等）    | `[style] インデント統一`            |
| `[clean]`    | 不要なコード・ファイルの整理                      | `[clean] 未使用importの削除`        |
| `[delete]`   | ファイルや機能そのものの削除                      | `[delete] 旧設定ファイルの削除`     |
| `[test]`     | テストの追加・修正                                | `[test] ログイン処理のテスト追加`   |
| `[core]`     | ビルドプロセス・CI/CD・補助ツール・依存関係の変更 | `[core] pyproject.tomlへの設定統合` |
| `[docs]`     | ドキュメントのみの変更                            | `[docs] CGT0902 詳細設計書の追加`   |
| `[WIP]`      | 作業の途中経過（Work In Progress）                | `[WIP] 決済フロー実装中`            |
| `[other]`    | 上記いずれにも当たらないもの                      | `[other] .gitignore 更新`           |

`[other]` は最後の手段とし、上記の種別で表現できる場合はそちらを優先してください。

---

## `[fix]` コミットの詳細

バグ修正 (`[fix]`) の場合は、コミットの本文（2行目以降）に以下の情報を
含めることを推奨します。どのようなバグがなぜ修正されたのかが明確になります。

**フォーマット:**
```
[fix] 修正内容の要約

Problem:
どのような問題（バグ）があったかを簡潔に説明

Solution:
どのように問題を解決したかを簡潔に説明

Closes #イシュー番号
```

**具体例:**
```
[fix] ログイン処理のエラー修正

Problem:
パスワードに特殊文字が含まれる場合、ログインできなかった。

Solution:
認証ルートに適切なデコード処理を追加した。

Closes #42
```
> `Closes #番号` と記述すると、このコミットが `main` ブランチにマージされた際に、関連するGitHub Issueを自動で閉じることができます。
