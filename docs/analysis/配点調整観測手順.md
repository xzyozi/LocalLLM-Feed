# 配点調整観測手順

- **対象**: `config/scoring.toml`、`public/data/function_provider_observations.json`
- **目的**: 再利用性を中心とする掲載基準を、同一入力に対して比較・再現・ロールバック可能な方法で調整する。
- **ステータス**: 運用手順

## 1. 原則

配点または掲載閾値を変更する前に、比較対象となる入力候補集合を固定する。比較ごとにプロファイルID、プロファイル版、設定ファイルSHA-256、入力データの取得日時、実行コミットを残す。PWC照合、科学計算ライブラリ、ML属性は検索・表示・観測だけに使い、直接加点しない。

TOMLの値を変更する場合は、同じ箇所のコメントに判断理由を書き、`profile.version`を増加させる。評価処理は設定の検証に失敗した場合、既定値に戻さず停止する。

## 2. 観測データ

パイプラインは`function_provider_observations.json`を出力する。`report_version: 3`では、評価ごとに提供形態、スコア内訳、信頼度乗数、PWC照合状態、所有者照会状態・種別・組織認証・学術ドメイン・アカウント年数帯を記録する。

`summary`には次の集計を保存する。

| 項目                           | 用途                                             |
| ------------------------------ | ------------------------------------------------ |
| `threshold_pass_rate`          | 掲載閾値を通過する候補の比率                     |
| `pwc_lookup_status_counts`     | 公式一致・非公式一致・未一致・照会失敗の偏り確認 |
| `owner_account_type_counts`    | User/Organizationなどの所有者分布                |
| `account_age_year_buckets`     | 照会不能を含むアカウント年数分布                 |
| `user_trust_multiplier_counts` | 信頼度乗数が結果へ与える偏り                     |
| `total_score_distribution`     | 総合点の平均・最小・最大                         |

PWCアーカイブが未一致または照会失敗であっても、品質や再利用性が低いとは判断しない。`not_found`と`failed`は必ず区別する。

## 3. 配点変更の比較手順

1. 現行設定でパイプラインを実行し、観測レポートと`repos.json`を安全な比較用フォルダへ保存する。
2. `config/scoring.toml`の配点・上限・閾値を変更し、コメントと`profile.version`を更新する。
3. **同じ候補入力**を用いて再実行し、新旧それぞれの設定ID・版・SHA-256を記録する。
4. `evaluations`の`repo_id`と`threshold_passed`を比較し、追加掲載・除外掲載のID一覧を作る。
5. 提供形態、シードカテゴリ、PWC照合状態、所有者種別ごとに通過率と総合点分布を比較する。


## 4. 採用・ロールバック基準

変更後に、ライブラリ・モジュール型アプリケーションの掲載比率が意図せず大幅に低下していないこと、特定シードカテゴリまたは所有者種別だけに偏っていないことを確認する。PWC一致率や学術ドメイン率の変化は、収集品質の観測値として扱い、単独では採否を決めない。

以下のいずれかに該当する場合は、変更前のTOMLを復元して再実行する。

- 再利用性の根拠が少ない提供形態だけが掲載を大きく増やした。
- ライブラリ提供型の候補が、説明できない理由で大きく除外された。
- 照会失敗の増加を品質低下と誤認している。
- 追加・除外されたID一覧をレビューできない。

ロールバック時も設定ハッシュと比較結果を残し、静的成果物は復元後の実行結果で置き換える。

## 5. PWCアーカイブの出典と制約

PWC照合は、Hugging Faceで公開されている`pwc-archive/links-between-paper-and-code`を使用する。このデータセットは2025-07-28時点の最終公開スナップショットであり、継続更新されないため、現在の登録状況を保証しない。照合はGitHub URLに限定し、PWCの公式性フラグを表示・観測するだけでスコアへ加算しない。

- [Papers with Code datasets](https://github.com/paperswithcode/paperswithcode-data)
- [PWC archive: links between paper and code](https://huggingface.co/datasets/pwc-archive/links-between-paper-and-code)
- [Hugging Face Dataset Viewer filter API](https://huggingface.co/docs/dataset-viewer/filter)

外部資料の説明はライセンス遵守のため要約・言い換えしています。
