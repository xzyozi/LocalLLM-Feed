# ADR-001: 関数提供型リポジトリを優先する

- **ステータス**: 採用
- **日付**: 2026-08-31
- **決定者**: ScholarRepo-Finder 開発チーム

## 背景

従来の選定は、科学計算・OR・ML系の依存ライブラリ数、論文リンク、ディレクトリ構造を主な根拠としていた。この方式では、複数のML依存を持つプロジェクトが有利になる一方、C/C++のヘッダ公開型実装や、モジュールに分割されたシミュレーション実装の再利用性を十分に表せない。

利用者が主に探したいのは、研究・検証コードから呼び出せる関数、モジュール、ライブラリ、およびそれに準ずるモジュール型アプリケーションである。

## 決定

候補選定では、再利用可能な関数・モジュール・公開APIを提供するリポジトリを優先する。実行入口を持つ場合も、ロジックがモジュール化され、外部利用できる境界が確認できれば対象に含める。

MLであること、Papers with Codeへの掲載、またはML系依存ライブラリの数は、品質・再利用性の直接加点には使用しない。これらは検索・説明用の属性として扱う。

配点、評価軸の上限、ハードフィルター、掲載閾値、信頼度乗数は、リポジトリ管理する `config/scoring.toml` を唯一の設定源とする。初期プロファイルは `reusability-v1` とし、設定検証に失敗した場合は暗黙に既定値へ戻さず評価を停止する。適用した設定のID、版、ハッシュを観測レポートに記録し、評価結果を再現可能にする。Python 3.11以降の標準ライブラリ `tomllib` を使い、設定値と同じ場所にコメントで判断理由を残す。言語別の検出規則は配点設定と分離し、コード側で管理する。

## 理由

- 目的である「他の研究・検証コードから使える実装」を直接評価できる。
- 言語や分野に依存せず、C/C++の公開ヘッダ、Pythonのパッケージ、Rustのライブラリなどを同じ原則で評価できる。
- 特定の技術分野への偶発的な偏りを低減できる。

## トレードオフ

- 公開APIの自動判定は言語ごとに異なり、誤判定の可能性がある。
- モジュール型アプリケーションは、完全なライブラリ配布物より再利用手順が複雑な場合がある。
- スコア改定前後の掲載件数・分野構成を比較し、閾値を再調整する必要がある。
